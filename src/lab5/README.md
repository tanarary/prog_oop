# ЛР-5 — Функции как аргументы. Стратегии и делегаты

## 1. Цель работы

- Освоить передачу функций как аргументов в другие функции и методы
- Научиться применять встроенные функции высшего порядка: `map`, `filter`, `sorted`
- Понять концепцию паттерна «Стратегия» и реализовать его на Python
- Освоить `lambda`-выражения и их практическое применение
- Интегрировать функциональный стиль с объектно-ориентированным кодом из предыдущих ЛР (пациенты, больница)

## 2. Реализованные функции и стратегии

### 2.1. Функции-стратегии для сортировки

| Функция | Описание |
|---------|----------|
| `by_full_name` | Сортировка по ФИО пациента (алфавитный порядок) |
| `by_age` | Сортировка по возрасту |
| `by_temperature` | Сортировка по температуре тела |
| `by_days_in_hospital` | Сортировка по количеству дней в стационаре |
| `by_multiple_criteria` | Сортировка по статусу + температуре (приоритетная) |

### 2.2. Функции-фильтры

| Функция | Описание |
|---------|----------|
| `is_active` | Отбирает только пациентов на лечении |
| `is_emergency` | Отбирает только экстренных пациентов |
| `is_critical` | Отбирает критических пациентов (температура ≥ 39° или тяжесть ≥ 4) |
| `make_temperature_filter(min, max)` | Фабрика: создает фильтр по диапазону температур |
| `make_age_filter(min, max)` | Фабрика: создает фильтр по возрастному диапазону |

### 2.3. Функции высшего порядка и фабрики

| Функция/Фабрика | Описание |
|----------------|----------|
| `sorted(collection, key=func)` | Встроенная сортировка с пользовательским ключом |
| `filter(predicate, collection)` | Встроенная фильтрация по условию |
| `map(func, collection)` | Встроенное преобразование элементов |
| `make_temperature_filter(min, max)` | Фабрика: создает фильтр по диапазону температур |
| `make_age_filter(min, max)` | Фабрика: создает фильтр по возрастному диапазону |
| `make_emergency_multiplier(weight)` | Фабрика: создает функцию веса для экстренных пациентов |

### 2.4. Паттерн «Стратегия» (callable-объекты)

Реализованы три класса стратегий сортировки:

| Стратегия | Описание |
|-----------|----------|
| `SortByNameStrategy` | Сортировка пациентов по ФИО |
| `SortByAgeStrategy` | Сортировка пациентов по возрасту |
| `SortByPriorityStrategy` | Приоритетная сортировка: критические → экстренные → остальные |

Все стратегии реализованы как callable-объекты (с методом `__call__`), что позволяет:
- Передавать их как обычные функции
- Легко заменять одну стратегию на другую без изменения кода коллекции

### 2.5. Методы коллекции

В класс `PatientRegistry` добавлены методы:

| Метод | Описание |
|-------|----------|
| `sort_by(key_func, reverse)` | Сортирует коллекцию по переданной функции-ключу |
| `filter_by(predicate)` | Возвращает новую коллекцию с отфильтрованными элементами |
| `apply(func)` | Применяет функцию к каждому элементу |
| `map_to(transform_func)` | Преобразует коллекцию с помощью `map()` |

### Сценарий 6: Lambda vs именованная функция

![alt text](/src/lab5/img/sc6.png)

**Что демонстрируется:**
- Lambda-выражения и именованные функции дают одинаковый результат
- Сравнение в `sorted()` и `filter()`

**sorted():**
- Lambda `lambda p: p.age`: сортировка по возрасту
- Именованная функция `by_age`: точно такой же результат

**filter():**
- Фабрика `make_age_filter(30, 60)`: фильтр пациентов 30-60 лет
- Lambda `lambda p: 30 <= p.age <= 60`: точно такой же результат

**Вывод:** Lambda удобна для простых одноразовых операций, именованная функция - для переиспользуемой логики. Результат идентичен.

## 4. Вывод

В ходе выполнения лабораторной работы были изучены и применены на практике следующие концепции:

### 4.1. Передача функций как аргументов
Реализованы методы `sort_by(key_func)` и `filter_by(predicate)`, которые принимают функции в качестве аргументов. Это позволяет гибко настраивать поведение коллекции пациентов без изменения её кода.

### 4.2. Lambda-выражения
Lambda-выражения использованы для:
- Сортировки: `sorted(patients, key=lambda p: p.age)`
- Фильтрации: `filter(lambda p: p.has_fever(), patients)`
- Преобразования: `map(lambda p: p.age, patients)`

### 4.3. Функции высшего порядка
Применены встроенные функции:
- `map()` — для преобразования пациентов в строки и словари
- `filter()` — для отбора экстренных и критических пациентов
- `sorted()` — для сортировки по различным критериям

### 4.4. Фабрики функций (замыкания)
Созданы функции, возвращающие другие функции:
- `make_temperature_filter(min_temp, max_temp)` — создает фильтр для заданного диапазона температур
- `make_age_filter(min_age, max_age)` — создает фильтр для возрастного диапазона

Это позволяет параметризовать поведение и избегать дублирования кода.

### 4.5. Паттерн «Стратегия»
Реализован через callable-объекты (классы с методом `__call__`):
- Стратегии взаимозаменяемы без изменения кода коллекции
- Можно хранить состояние внутри объекта стратегии
- Легко добавлять новые стратегии (например, сортировку по группе крови)

### 4.6. Цепочки операций
Реализован fluent-интерфейс для последовательного применения:
- `filter_by()` → `sort_by()` → `apply()`
- Каждая операция возвращает коллекцию для продолжения цепочки

### 4.7. Интеграция с ООП
Функциональный стиль успешно интегрирован с существующими классами:
- `Patient` (из ЛР-1)
- `EmergencyPatient` и `ChronicPatient` (из ЛР-3)
- `PatientRegistry` (из ЛР-2, расширен в ЛР-5)

Это демонстрирует мощь Python как мультипарадигмального языка, позволяющего сочетать объектно-ориентированный и функциональный подходы в одном проекте.
