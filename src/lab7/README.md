# Лабораторная работа №7 — Консольное приложение

## 1. Цель работы

Объединить все знания, полученные в ЛР1–ЛР6, в единое работающее приложение. Реализовать интерактивный CLI-интерфейс с меню и вводом пользователя.

**Применённые навыки:**
- Объектно-ориентированное программирование (классы Patient, EmergencyPatient, ChronicPatient)
- Работа с коллекциями (PatientRegistry)
- Собственные исключения (PatientNotFoundError, DuplicatePatientError, InvalidPatientDataError)
- Функции высшего порядка (сортировка, фильтрация через стратегии)
- Аннотации типов (typing)
- Работа с JSON (сохранение/загрузка данных)
- Разделение на слои (CLI → бизнес-логика → хранение данных)

## 2. Описание CLI

### 2.1 Пункты меню

| Пункт | Описание |
|-------|----------|
| 1 | Добавить пациента (обычный, экстренный, хронический) |
| 2 | Показать всех пациентов (таблица) |
| 3 | Найти пациента по ID |
| 4 | Найти по части ФИО |
| 5 | Изменить диагноз |
| 6 | Удалить пациента (с подтверждением y/n) |
| 7 | Фильтрация (активные, экстренные, критические, по температуре/возрасту) |
| 8 | Сортировка (по имени, возрасту, температуре) |
| 9 | Выписать пациента (с проверкой температуры) |
| 0 | Выход (автосохранение) |

### 2.2 Обработка ошибок ввода

- Неверный пункт меню → "❌ Неверный пункт!"
- Ввод строки вместо числа → "Ошибка: введите число"
- Некорректные данные (возраст, температура, группа крови) → сообщение валидатора
- Удаление несуществующего пациента → "❌ Пациент не найден"
- Выписка с температурой → "❌ Нельзя выписать пациента с повышенной температурой"

### 2.3 Сохранение/загрузка данных

- При запуске: автоматическая загрузка из `data/patients.json`
- При выходе: автоматическое сохранение в `data/patients.json`
- Папка `data` и файл создаются автоматически
- Формат JSON сохраняет тип пациента, ФИО, возраст, группу крови, диагноз, температуру, статус, даты, для экстренных — степень тяжести, для хронических — заболевание и стаж

## 4. Вывод

В ходе выполнения лабораторной работы были изучены и применены на практике следующие концепции:

### 4.1 Аннотации типов
Все функции и методы имеют аннотации типов. Параметры `(full_name: str, age: int)`, возвращаемые значения `-> Patient`, `-> List[Patient]`, `-> None`. Переменные типизированы явно.

### 4.2 CLI-интерфейс
Реализовано меню с 10 пунктами. Цикл обработки команд, обработка ошибок ввода, валидация данных предметной области.

### 4.3 Обработка исключений
Созданы собственные исключения: `PatientNotFoundError`, `DuplicatePatientError`, `InvalidPatientDataError`. Перехват и обработка в CLI.

### 4.4 Работа с файлами (оценка 5)
Автозагрузка и автосохранение в JSON. Автоматическое создание папки `data` и файла. Полная сериализация/десериализация иерархии классов.

### 4.5 Практическая польза
Разработанное приложение демонстрирует:
- ООП (наследование Patient → EmergencyPatient, ChronicPatient)
- Работу с коллекциями (PatientRegistry с filter_by, sort_by, apply)
- Функции высшего порядка (сортировка через key-функции, фильтрация через предикаты)
- Работу с JSON (сохранение и загрузка)
- Полный цикл CRUD + специфические операции (выписка, фильтрация, сортировка)
